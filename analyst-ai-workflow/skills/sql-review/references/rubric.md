# 채점 기준 (10점)

| 항목 | 배점 | 보는 것 |
|------|------|---------|
| 정답 | 4 | 결과 수치가 기대값과 같은가. 엣지 케이스(0건, NULL, 경계일)에서도 같은가 |
| grain | 2 | 결과 한 행의 단위, 분모 모집단, 조인 단위가 문제와 맞는가 |
| 효율 | 2 | 중복 스캔, 불필요한 서브쿼리, 행을 불린 뒤 DISTINCT로 줄이는 패턴이 없는가 |
| 실무 자연스러움 | 2 | 사람이 읽고 고칠 수 있는가. CTE 이름과 역할, 흔한 함수 사용 |

## 정답 감점

| 상황 | 감점 |
|------|------|
| 결과 수치가 다름 (로직 오류) | 오류 하나당 2점, 최대 4점 |
| 엣지 케이스에서만 다름 | 1점 |
| 결과는 같지만 우연히 같음 (데이터가 바뀌면 틀림) | 1점, 이유를 반드시 설명 |

## grain에서 자주 보는 오류

| 오류 | 증상 | 확인 방법 |
|------|------|-----------|
| fan-out | 1:N 조인 뒤 SUM이 부풀려짐 | 조인 전후 행 수 비교 |
| 분모 모집단 | 비율의 분모가 "행동한 사람"으로 줄어듦 | 분모 CTE만 따로 COUNT |
| 집계 누락 | 0건인 그룹이 결과에서 사라짐 | LEFT JOIN 기준 테이블이 모집단인지 |
| 정수 나눗셈 | 비율이 0 또는 1로만 나옴 | 분자나 분모에 1.0 곱하기 |
| 필터 위치 | 첫 구매 판정 전에 기간을 잘라 첫 구매가 바뀜 | 첫 구매를 전체 기간에서 구한 뒤 기간을 거는지 |

## 실무 자연스러움 감점

- CTE 이름이 순서만 말함 (`step1`, `tmp2`, `final`): 0.5점
- 한 CTE에 역할 셋 이상 (모집단 정의 + 집계 + 비율 계산): 0.5점
- 방언 전용 함수를 이유 없이 사용해 이식성이 떨어짐: 0.5점
- 주석이 코드를 그대로 읽어 줌 (`-- user_id로 그룹핑`): 0.5점
