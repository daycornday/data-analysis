# 서버 로그와 클라이언트 로그

> 같은 "결제 완료"라도 어디서 기록했는지에 따라 숫자가 다르다. 차이는 버그가 아니라 구조에서 나온다.

## 어디서 기록되나

| | 클라이언트 로그 | 서버 로그 |
|---|---|---|
| 기록 위치 | 브라우저, 앱 안의 SDK가 보낸다 | 서버가 요청을 처리하면서 DB나 로그에 남긴다 |
| 잘 아는 것 | 화면에서 일어난 행동 (노출, 클릭, 스크롤) | 상태가 바뀐 사실 (가입, 주문, 결제 승인) |
| 모르는 것 | 서버에서 확정된 결과 (승인 실패, 환불) | 서버를 부르지 않은 행동 |
| 주로 쓰는 곳 | 퍼널, UX 분석, 마케팅 귀속 | 매출, 주문 수, 정산 |

## 식당 비유

| 식당 | 데이터 |
|---|---|
| 손님이 메뉴판을 넘겨 보고, 이 메뉴 저 메뉴를 가리키는 것 | 클라이언트 이벤트 (스크롤, 탭 전환, 드롭다운) |
| 주방에 들어간 주문서 | 서버 요청 |
| 계산대 영수증 | 서버의 결제 기록 |
| 홀 직원이 수첩에 적는 손님 행동 메모 | 클라이언트 SDK 로그. 직원이 바쁘거나 손님이 가려 버리면 빠진다 |
| 주방이 모르는 것 | 메뉴판을 보다가 그냥 나간 손님 |

영수증(서버)은 돈이 오간 사실을 정확히 안다. 하지만 손님이 무엇을 망설였는지는 홀 메모(클라이언트)에만 있다.

## 클라이언트 기록이 유실되는 이유

- 광고 차단기: 분석 도구 도메인과 스크립트 이름을 목록으로 막는다.
- 브라우저 추적 차단: 서드파티 쿠키 차단, 스크립트 쿠키 수명 단축으로 같은 사람이 다른 사람으로 갈라진다.
- 동의 거부: 쿠키 동의 배너에서 거부하면 SDK가 아예 보내지 않거나 익명으로만 보낸다.
- 이탈 중 전송 중단: 버튼을 누르자마자 페이지가 넘어가거나 탭을 닫으면 요청이 끊긴다. `sendBeacon`이나 배치 전송으로 줄일 수 있지만 0은 아니다.
- 네트워크: 모바일 앱은 오프라인일 때 쌓아 뒀다 보내는데, 앱을 지우거나 큐가 넘치면 버려진다. 늦게 도착한 이벤트는 집계가 끝난 날짜로 들어온다.
- JS 에러: 같은 페이지의 다른 스크립트가 먼저 터지면 추적 코드가 실행되지 않는다.

이 유실은 무작위가 아니다. 광고 차단기를 쓰는 사람, 특정 브라우저 사용자, 저사양 기기 사용자에게 몰린다. 그래서 전체 숫자가 줄어드는 것보다 세그먼트 비교가 휘는 것이 더 위험하다.

## "서버 = 무조건 정확"은 반만 맞다

두 축을 나눠 봐야 한다.

- 유실 축: 서버는 요청을 받은 이상 거의 빠뜨리지 않는다. 이 축에서는 서버가 정확하다.
- 정의 축: 서버 로그의 "주문"이 분석가가 말하는 "주문"과 같다는 보장은 없다. 테스트 계정, 내부 직원 주문, 결제 실패 후 재시도, 부분 취소, 환불, 봇 요청이 같은 테이블에 섞여 있다. 어느 상태를 주문으로 셀지는 서버가 정해 주지 않는다.

즉 서버 숫자는 "빠짐이 적은 숫자"이지 "정의가 맞는 숫자"가 아니다. 클라이언트와 서버 숫자가 다를 때, 차이의 일부는 유실이고 일부는 정의 차이다. 둘을 나눠서 설명해야 한다.

## 서버가 모르는 행동

서버를 부르지 않고 화면 안에서 끝나는 행동은 클라이언트에서만 보인다.

- 드롭다운 열기, 옵션 고르다 취소
- 탭 전환, 아코디언 펼치기
- 스크롤 깊이, 화면에 머문 시간
- 입력하다 지운 검색어, 폼 중간 이탈
- 이미 받아 둔 데이터 안에서의 정렬, 필터 변경
- 툴팁, 미리보기에 마우스 올리기

이런 질문("어디서 망설이나")은 서버 로그로 답할 수 없다. 클라이언트 유실을 감안하고 쓴다.

## 분석가 체크리스트

- [ ] 이 지표의 이벤트는 클라이언트에서 오나, 서버에서 오나. 이벤트 정의서에 적혀 있나
- [ ] 같은 사건을 양쪽에서 다 기록한다면, 기간을 맞춰 건수를 비교해 봤나 (서버 대비 클라이언트 비율)
- [ ] 그 비율이 플랫폼, 브라우저, 앱 버전, 국가별로 다른가. 다르면 세그먼트 비교는 보정 없이 하지 않는다
- [ ] 서버 숫자에서 테스트 계정, 내부 계정, 실패, 취소, 환불을 어떻게 다뤘는지 정의했나
- [ ] 늦게 도착하는 이벤트를 몇 일까지 기다렸다 집계를 확정하나
- [ ] 동의 거부 사용자는 지표에서 어떻게 보이나 (빠지나, 익명으로 남나)
- [ ] 클라이언트와 서버를 잇는 키(주문 id, 세션 id)가 있나. 있으면 건 단위로 대조할 수 있다
- [ ] 매출, 주문 같은 돈 지표는 서버 기준으로, 행동 퍼널은 클라이언트 기준으로 정하고 섞을 때 표시했나
