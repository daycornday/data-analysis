# 기능 사용 비중 세그먼테이션 (CLR + GMM)

기능 사용 비중으로 유저를 나눌 때, 비중을 그대로 k-means에 넣어도 되는지 늘 헷갈렸습니다. 합이 1로 묶인 데이터는 다르게 다뤄야 한다는 얘기를 듣고, 정답을 심어 둔 합성 데이터로 얼마나 차이가 나는지 직접 확인해 봤습니다.

## 왜 비중이 문제인가
"어떤 유저가 어떤 기능을 주로 쓰나"로 세그먼트를 만들 때는 사용량 자체보다 사용 비중(기능별 횟수 / 전체 횟수)을 쓰는 경우가 많습니다. 헤비 유저와 라이트 유저를 같은 기준으로 비교하려는 것입니다.
그런데 비중은 합이 1로 묶인 조성 데이터라서, 보통의 숫자 열처럼 유클리드 거리로 다루면 작은 비중에서 생기는 의미 있는 차이를 놓칩니다.
이 문제가 실제로 얼마나 큰지 합성 데이터로 재현해 보고, CLR 변환과 GMM으로 정답 세그먼트를 얼마나 되찾는지 재 봤습니다.

## 결과
정답을 심은 합성 데이터에서 원자료 k-means는 ARI 0.54, CLR 변환 뒤 GMM은 0.88이 나왔고, BIC는 정답 군집 수 4를 골랐습니다.

- 기능 5종 사용 비중을 가진 합성 유저 6,000명(정답 세그먼트 4개)에서 CLR + GMM의 BIC는 군집 4개에서 가장 낮았습니다.
- 시드만 바꿔 데이터를 10번 새로 만든 평균 ARI는 원자료 + k-means 0.54, 원자료 + GMM 0.83, CLR + k-means 0.87, CLR + GMM 0.88이었습니다. 차이의 대부분은 CLR 변환에서 나왔습니다.
- 원자료 k-means는 "편집 집중" 세그먼트를 편집 비중의 높낮이로 둘로 쪼갰고(777명, 1,360명), 협업 비중만 다른 "편집 + 협업" 세그먼트(879명)를 그 두 군집에 반씩 흩어 놓았습니다.
- CLR + GMM이 찾은 세그먼트의 유료 전환율은 3.9%에서 13.3%까지 달랐습니다(카이제곱 90.1, 자유도 3, p = 2.1e-19). 전환율이 가장 높은 "편집 + 협업"(13.3%)은 원자료 k-means로는 보이지 않던 세그먼트입니다.
- 유저당 사용 횟수가 적으면(평균 30회) 0회 칸이 10%가 되고, CLR + GMM의 ARI가 0.31로 떨어져 원자료 k-means(0.39)보다 못했습니다. CLR은 충분히 쓴 유저에게 써야 하는 방법으로 보입니다.

## 어떻게 했나
1. 합성 데이터는 세그먼트 4개마다 평균 사용 비중을 정하고(`synth.SEGMENTS`), 로그 비중에 정규 잡음(표준편차 0.35)을 더해 유저별 비중을 만들었습니다. 유저별 전체 사용 횟수(평균 500회)를 그 비중대로 다항분포로 나눠 기능별 횟수를 만들고, 세그먼트별 정답 전환율(3%, 6%, 9%, 14%)로 유료 전환 여부를 뽑았습니다. 결과는 `data/feature_usage.csv`에 있습니다.
2. 원자료를 그대로 쓰면 생기는 문제는 두 가지로 정리했습니다.
   - 합이 1이라는 제약 때문에 한 기능 비중이 오르면 다른 비중은 반드시 내려갑니다. 비중끼리 음의 상관이 데이터와 상관없이 생기고, 5개 열 중 하나는 나머지로 정해집니다.
   - 의미는 상대 비율에 있는데 거리는 절대 차이를 봅니다. 협업 2%와 11%는 5배 넘게 다른 사용 습관이지만 유클리드 거리로는 0.09라서, 편집 55%와 64%의 차이와 같은 크기로 취급됩니다. 그래서 k-means는 큰 비중(편집)의 높낮이로 군집을 나누고, 작은 비중의 차이로 갈리는 세그먼트를 놓칩니다.
3. 0회 기능은 로그를 쓸 수 없어서 횟수에 0.5를 더한 뒤 비중으로 바꿨습니다. 그다음 중심 로그비(CLR) 변환을 했습니다.
   $$\mathrm{clr}(x)_j = \log \frac{x_j}{g(x)}, \qquad g(x) = \Big(\prod_{k=1}^{D} x_k\Big)^{1/D}$$
   이렇게 하면 비율이 같을 때 사용량이 달라도 값이 같고, 2% 대 11%처럼 작은 비중의 상대 차이가 log 척도에서 1.7만큼 벌어집니다.
4. CLR 좌표는 합이 0이라 마지막 열을 빼고 4개 열로 GMM(공분산 full, 초기값 5번)을 맞췄습니다. 군집 수 1~8개의 BIC를 비교해 가장 낮은 값을 골랐습니다.
5. 같은 군집 수로 원자료 k-means, 원자료 GMM, CLR k-means, CLR GMM을 돌리고, 정답과의 일치를 ARI(adjusted Rand index, 1이면 완전 일치, 0이면 무작위 수준)로 쟀습니다. 데이터를 10번 새로 만들어 반복했습니다.
6. 군집별 대표 비중은 CLR 평균을 다시 비중으로 되돌린 값(조성 데이터의 기하 평균)을 썼습니다. 전환율 구간은 Wilson 95% 구간, 세그먼트 간 차이는 카이제곱 검정으로 봤습니다.

## 아쉬운 점과 다음에 해 볼 것
세그먼트는 유저를 설명할 뿐 무엇을 하라고 알려 주지는 않습니다. "편집 + 협업" 세그먼트의 전환율이 높다고 해서 협업 기능을 권하면 전환이 오른다는 뜻은 아닙니다. 원래 유료를 살 사람이 협업을 쓰는 것일 수도 있습니다. 다음에는 세그먼트별로 실험을 설계해 보려고 합니다. 예를 들어 "편집 집중" 유저에게 협업 기능 노출을 무작위로 늘려 전환율이 오르는지 보는 식입니다.

사용량이 적은 유저가 마음에 걸립니다. 0회 칸이 많으면 pseudocount 값이 결과를 좌우하고 CLR이 잡음에 휘둘립니다(위 표의 30회 줄). 실무라면 최소 사용 횟수 이상인 유저만 세그먼트에 넣고, 나머지는 "저활동" 세그먼트로 따로 두는 편이 나아 보입니다. 기능을 아예 몰라서 0이 구조적으로 많다면, 0 여부를 별도 변수로 다루는 편이 낫습니다.

합성 데이터가 CLR + GMM에 유리하게 만들어졌습니다. 잡음을 로그 비중 공간에서 정규분포로 넣었기 때문에 CLR + GMM의 가정과 생성 과정이 잘 맞습니다. 실제 데이터에서는 차이가 이보다 작을 수 있습니다.

군집 수를 BIC만으로 정하면 곤란할 것 같습니다. 실제 데이터에서는 BIC가 계속 내려가는 경우가 많다고 합니다. 세그먼트 수는 운영 가능한 수(팀이 다르게 대할 수 있는 수)와 함께 정해야 합니다.

한 시점의 비중만 썼습니다. 탐색형에서 편집 집중으로 옮겨 가는 것 같은 세그먼트 간 이동은 보지 않았습니다.
