# 마르코프 체인 성장 시뮬레이터

리텐션 과제를 고를 때 "어느 단계를 고쳐야 활성 유저가 가장 많이 늘어나나"라는 질문에 자신 있게 답하기가 어려웠습니다. 퍼널 전환율 표만 보고 가장 낮은 단계를 고르는 게 맞는지 궁금해서, 유저 상태 전이를 마르코프 체인으로 놓고 직접 계산해 봤습니다.

## 질문을 어떻게 잡았나
리텐션 개선 과제는 늘 후보가 많습니다. 온보딩, 이탈 위험 알림, 휴면 유저 복귀 캠페인이 같은 리소스를 두고 경쟁합니다.
퍼널 단계별 전환율만 보면 "가장 낮은 단계"를 고치고 싶어지는데, 전이는 서로 이어져 있어서 한 단계를 고친 효과가 다음 달, 그다음 달로 번집니다.
그래서 월간 상태 전이를 마르코프 체인으로 놓고, 전이 하나를 같은 크기(+1%p)로 바꿨을 때 12개월 뒤 활성 유저가 얼마나 달라지는지로 레버의 크기를 비교해 봤습니다.

## 결과
합성 데이터에서는 "활성 유지"를 1%p 올렸을 때 활성 유저가 가장 많이 늘었고(+442명), "휴면 → 복귀"가 그다음(+240명)이었습니다. 이 순위는 부트스트랩 200회에서 한 번도 바뀌지 않았습니다.

- 합성 로그(유저 48,000명, 유저-월 311,733행)에서 추정한 전이행렬은 정답과의 최대 오차가 0.0084였고, 유저 단위 부트스트랩 95% 구간이 정답 22칸을 모두 덮었습니다.
- 매달 신규 2,000명이 들어올 때 활성 유저(첫 달 활성 + 활성 + 복귀)는 현재 7,930명에서 12개월 뒤 8,545명으로 늘고, 정상상태 8,838명에 다가갑니다.
- 전이 하나를 +1%p 개선했을 때 12개월 뒤 활성 유저는 활성 → 활성 +442명(95% 구간 429~451), 휴면 → 복귀 +240명, 이탈 위험 → 활성 +111명, 신규 → 첫 달 활성 +98명, 첫 달 활성 → 활성 +69명, 복귀 → 활성 +31명만큼 늘었습니다.
- 레버의 크기는 대체로 출발 상태에 머무는 인원이 정하는 것으로 보입니다. 활성(6,300명)과 휴면(4,746명)은 사람이 많아서 1%p가 매달 큰 인원으로 바뀝니다. 복귀(508명)는 전환율을 올려도 움직이는 사람이 적습니다.
- 다만 이 순위는 "같은 1%p를 얻는 비용이 같다"고 가정하고 매긴 것입니다. 비용을 붙이는 일은 따로 해야 합니다(아래 아쉬운 점 참고).

표를 보면서 정리한 내용입니다.

1위와 2위는 구간이 겹치지 않을 만큼 차이가 크고, 부트스트랩 200회에서 1위가 바뀐 적이 없습니다. 추정 오차 때문에 순위가 흔들리는 상황은 아니라고 판단했습니다.

개선과 악화가 거의 대칭으로 나왔습니다. 1%p 수준에서는 효과가 선형에 가깝다는 뜻으로 보이고, 그래서 같은 표를 "어느 전이가 나빠지면 가장 아픈가"로도 읽을 수 있습니다.

12개월 효과는 정상상태 효과의 60~70% 수준이었습니다. 1년 안에 효과가 다 나타나지는 않습니다.

같은 1%p라도 난이도는 다릅니다. 휴면 → 복귀의 +1%p는 0.10을 0.11로, 상대적으로 10% 올리는 일입니다. 활성 → 활성의 +1%p는 활성의 직접 이탈 1%를 거의 0으로 만드는 일입니다.

![12개월 투영](outputs/projection.png)

지금 그대로 두면 12개월 뒤 8,545명이고, 활성 → 활성을 1%p 올리면 8,987명입니다. 파란 띠는 전이행렬 추정 불확실성만 반영한 구간입니다.

상태별 현재 인원과 정상상태 인원은 `outputs/steady_state.csv`에 정리했습니다.

## 어떻게 했나
1. 상태는 월 단위 7개로 나눴습니다. 신규(가입한 달), 첫 달 활성, 활성, 이탈 위험(활동이 크게 줄어든 달), 휴면(활동 없음), 복귀(휴면 뒤 다시 활동), 이탈(정의상 되돌아오지 않는 흡수 상태)입니다. 활성 유저 수는 첫 달 활성 + 활성 + 복귀로 셌습니다.
2. 합성 로그는 `chain.true_transition_matrix()`의 정답 행렬로 만들었습니다. 24개월 동안 매달 2,000명이 들어오는 상태 로그이고, `data/state_logs.csv.gz`에 있습니다.
3. 전이행렬은 같은 유저의 연속한 두 달을 (이번 달, 다음 달) 쌍으로 세고 행 합으로 나눠 추정했습니다.
   ```
   P_hat[i, j] = n(i → j) / sum_k n(i → k)
   ```
4. 신뢰구간은 부트스트랩 200회로 구했습니다. 이때 전이 쌍이 아니라 유저를 복원추출했습니다. 한 유저의 전이들은 서로 독립이 아니어서, 유저 단위로 묶어 뽑아야 구간이 너무 좁아지지 않습니다.
5. 정상상태는 매달 신규 a명이 들어오고 이탈은 빠져나가는 열린 시스템으로 보고 구했습니다. 이탈을 뺀 부분행렬을 Q라 하면 인원 x는 다음 고정점으로 수렴합니다.
   $$x = xQ + a \quad\Rightarrow\quad x = a\,(I - Q)^{-1}$$
6. 12개월 투영은 관측 마지막 달의 상태별 인원에서 출발해 `x(t+1) = x(t) P + a`를 12번 반복했습니다.
7. 민감도 분석에서는 레버 6개(좋은 쪽 전이)마다 확률을 +1%p 올리고, 같은 행에서 가장 나쁜 도착지(이탈, 없으면 휴면, 없으면 이탈 위험)에서 1%p를 덜어 행 합을 1로 맞췄습니다. 12개월 뒤 활성 유저를 기준선과 비교하고, -1%p 악화도 같은 방식으로 계산해 토네이도 그림으로 그렸습니다. 부트스트랩 행렬 200개 각각에 같은 계산을 반복해서 증가량의 95% 구간과 순위가 얼마나 안정적인지도 봤습니다.

## 아쉬운 점과 다음에 해 볼 것
마르코프 가정(기억 없음)을 그대로 썼습니다. 다음 달 상태가 이번 달 상태만으로 정해진다고 본 건데, 실제로는 휴면 3개월째와 1개월째 유저의 복귀 확률이 다를 것으로 보입니다. 휴면 기간을 상태로 쪼개거나(휴면 1개월, 2개월 이상) 2차 마르코프로 넓혀서 확인해 볼 생각입니다.

전이확률이 시간에 따라 변하지 않는다고(정상성) 가정했습니다. 계절성, 제품 변경, 가입 코호트 차이가 있다면 기간을 나눠 추정하고 행렬이 같은지 먼저 검정해야 합니다.

개선 가능성과 비용은 따로 봐야 합니다. 이 분석은 "1%p를 얻었을 때의 가치"만 알려 주고, 그 1%p를 얻는 비용이나 실제로 움직일 수 있는 폭은 알려 주지 않습니다. 다음에는 레버별로 "1%p당 비용"이나 과거 실험에서 실제로 움직인 폭을 붙여, 가치 대비 비용으로 순위를 다시 매겨 보려고 합니다.

한 번에 레버 하나만 바꿨습니다. 두 레버를 같이 고치면 효과가 단순 합과 다를 수 있습니다.

매달 신규 수를 2,000명으로 고정했습니다. 활성 유저가 늘면서 추천으로 신규가 느는 효과는 넣지 않았습니다.

합성 데이터라서 숫자는 방법을 확인하기 위한 것입니다. 실제 서비스에 쓰려면 무엇을 활동으로 볼지, 상태 정의부터 합의해야 합니다.
