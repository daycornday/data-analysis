# 실험 결과 보고서

목적: 결과표를 받은 사람이 "그래서 출시하나"를 한 화면 안에서 판단할 수 있게 한다. 순서를 지키는 이유는 앞 단계가 깨지면 뒤 단계 숫자를 믿을 수 없기 때문이다.

## 먼저 읽을 것
- `references/checklist.md`: 단계별 확인 항목과 멈춤 조건
- `references/readout-template.md`: 보고서 양식. 이 양식 그대로 채운다

## 입력으로 받을 것
없으면 추정하지 않고 사용자에게 묻는다.
- 사전에 정한 가설, 1차 지표, 최소 검출 효과(MDE), 계획 표본, 실험 기간
- 그룹별 배정 비율 (예: 50:50)
- 사용자 단위 원자료 또는 그룹별 집계 (사용자 수, 전환 수, 지표 합과 분산)

## 절차

### 1. 데이터 품질 (멈춤 조건 있음)
- 그룹별 사용자 수로 SRM 검정(카이제곱 적합도)을 한다. p < 0.001이면 **효과 해석을 멈추고** 원인 후보(노출 기록, 필터, 리다이렉트, 배정 단위)를 보고서 맨 위에 적는다
- 실험 기간이 계획과 같은지, 요일 주기를 한 바퀴 이상 덮는지 확인한다

```python
from scipy.stats import chisquare
stat, p = chisquare([n_control, n_treatment], f_exp=[total * 0.5, total * 0.5])
```

### 2. 검정력 점검
- 실제 표본이 사전 계산한 표본에 도달했는지 본다
- 결과가 유의하지 않을 때 "효과 없음"이라고 쓰지 않는다. "이 표본으로는 MDE보다 작은 효과를 가려낼 수 없다"고 쓴다
- 관측된 효과로 사후 검정력을 계산하지 않는다. p값을 다시 쓴 것에 불과하다

### 3. 1차 지표
- 효과 크기(절대 차이, 상대 차이)와 95% 신뢰구간을 같이 쓴다. p값만 쓰지 않는다
- 비율 지표는 분모 단위와 배정 단위가 같은지 확인한다. 다르면(예: 사용자 배정, 세션 분모) 델타 방법이나 사용자 단위 집계로 분산을 다시 구한다

### 4. 다중 비교
- 2차 지표가 여러 개면 Holm(가족 오류율) 또는 BH(거짓 발견율)로 보정하고, 어떤 방법을 왜 썼는지 한 줄 남긴다
- 결과를 보고 나서 고른 세그먼트 분석은 "탐색"으로 표시한다. 결정 근거로 쓰지 않고 다음 실험 가설로 넘긴다

### 5. 가드레일
- 사전에 정한 가드레일 지표(이탈, 오류율, 응답 시간 등)가 나빠지지 않았는지 본다. 가드레일은 "나빠지지 않았다"를 보는 것이라 비열등성 기준을 쓴다

### 6. 실무 해석과 결정
- 통계적 유의와 실무 유의를 나눠 쓴다. 신뢰구간 하한이 출시 비용을 넘는지 본다
- 초기 효과(노벨티)가 의심되면 주차별 효과 추이를 붙인다
- 결정은 셋 중 하나로 쓴다: 출시 / 중단 / 재실험 (재실험이면 무엇을 바꾸는지)

## 사람이 확인할 지점
보고서에 `[확인 필요]`를 남기고 넘어가는 자리다. 사용자가 답하기 전에는 결정 문단을 쓰지 않는다.
- SRM 원인 추정
- 출시 비용 기준선 (얼마 이상 효과여야 의미가 있나)
- 세그먼트 결과를 결정에 반영할지

## 하지 말 것
- SRM이 걸린 실험의 효과 크기를 본문에 쓰기
- 유의하지 않은 결과를 "효과 없음"으로 쓰기
- 실행하지 않은 계산의 숫자 쓰기. 모든 수치는 실행한 코드의 출력에서 가져온다
