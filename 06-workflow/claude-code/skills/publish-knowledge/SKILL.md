# 지식 글 발행 회차

목적: 공부한 내용을 같은 양식으로 꾸준히 쌓는다. 사람이 매번 지켜보지 않아도 되도록, 규칙은 이 문서가 아니라 검사 스크립트가 강제한다.

## 먼저 읽을 것 (매 회차, 생략 금지)
1. 백로그 파일 (`references/backlog.example.md` 형식): 무엇을 쓸지, 다음 글 번호
2. `references/post-format.md`: 글 양식과 검사 항목
3. 지난 회차 글 하나를 실제로 열어 모양을 맞춘다

## 인자
- `publish`: 검사 통과 시 공개 발행
- `dry-run`: 파일만 만들고 발행, 백로그 상태 변경은 하지 않는다
- 결과 파일 경로: 러너가 프롬프트로 넘긴다. 없으면 `$WORKFLOW_STATE_DIR/last_run.json`

## 절차

### 0. 시작
- 시작 시각을 기록한다 (결과 파일의 run_started)
- 이번 주제의 글 파일이 이미 있으면(지난 시험 실행, 업로드만 실패한 회차) 새로 쓰지 않는다. 다시 읽고 검사를 다시 돌린다
- 백로그에 todo가 3개 이하로 남았으면 새 주제 후보를 표 끝에 추가한다. 상태는 `proposed`로 두고 사람이 todo로 바꾸기 전에는 쓰지 않는다

### 1. 주제와 조사
- 백로그에서 상태가 todo인 첫 행을 고른다. 순서를 건너뛰지 않는다. 막히면 skip과 이유를 적고 다음 행
- 교재, 논문, 공개 기술 블로그 2~4개로 개념을 확인한다. 문장은 가져오지 않는다. 출처는 "더 읽을 것"에 링크

### 2. 숫자
- 글에 숫자가 들어가면 계산 스크립트를 만들어 실제로 실행한 값만 쓴다. 난수는 시드를 고정한다
- 확신이 없는 문장은 `[확인 필요]` 표시를 붙여 둔다. 이 표시가 남아 있으면 검사가 발행을 막는다

### 3. 쓰기
- `references/post-format.md` 양식대로 `posts/NN_주제.md`를 쓴다
- 쓰는 동안 PreToolUse 훅(doc_guard.py)이 금지 문자와 금지어를 막는다. 막히면 이유를 읽고 고쳐 쓴다

### 4. 검사 게이트
```
python -X utf8 automation/check_doc.py posts/NN_주제.md
```
- PASS: 5단계로
- FAIL: 발행하지 않는다. 두 번까지 고쳐 다시 검사한다. 세 번째도 실패면 멈추고 결과 파일에 실패 항목을 적는다

### 5. 발행
- 발행 명령은 환경변수 `PUBLISH_COMMAND`로 받는다 (예: 블로그 플랫폼 업로드 스크립트, 정적 사이트 빌드와 푸시). 계정 정보는 이 스킬과 저장소에 두지 않는다. 로그인 상태는 로컬 비공개 파일에만 있다
- 종료 코드 0: status published, 백로그 상태 published, 다음 글 번호 +1
- 로그인 만료나 업로드 실패: status draft, 원고는 남긴다. actions_needed에 사람이 할 일을 적는다
- `dry-run`이면 이 단계를 건너뛴다

### 6. 마무리 (중간에 실패해도 반드시)
결과 파일을 덮어쓴다. 형식은 `automation/last_run.example.json`과 같다.
- overall: published면 ok, draft면 partial, 검사 실패나 중단이면 failed
- actions_needed: 사람이 해야 할 일. 없으면 빈 배열
- 마지막 응답은 결과를 세 줄로 요약한다

## 사람이 확인할 지점
- `proposed` 상태의 새 주제 (사람이 todo로 바꿔야 쓴다)
- `[확인 필요]` 표시 (검사가 막는다)
- 발행 실패 후 남은 draft (다음 세션 시작 때 훅이 보여 준다)

## 하지 말 것
- 검사 실패 상태에서 발행
- 이미 발행한 글 수정. 오타를 찾아도 고치지 않고 actions_needed에 적는다
- 회사 자료, 사내 수치 사용. 공개 자료와 합성 데이터만
- `git push --force`, 기존 글 삭제
